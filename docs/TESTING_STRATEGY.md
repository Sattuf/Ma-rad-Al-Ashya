# استراتيجية الاختبار — معرض الأشياء

> الهدف: كل تغيير يُثبت أنه **صحيح، آمن، ولا يُثقل قاعدة البيانات** قبل دمجه، دون أن يصبح CI بطيئاً أو هشّاً.
> مرتبطة بـ [خطة إعادة البناء](REBUILD_PLAN.md).

## 1. الهرم

```
            ▲  E2E (Playwright/Flutter integration) — رحلات المستخدم الحرجة فقط          ⏳ المرحلة 3
           ▲▲  حمل (k6) — يدوي على staging، عتبات p95/أخطاء                              ✅
          ▲▲▲  عقود (gateway ↔ services ↔ clients)                                       ⏳ المرحلة 1
         ▲▲▲▲  تكامل — Postgres/Redis حقيقيان في CI                                     ✅ (auth, listings)
       ▲▲▲▲▲▲  وحدة — منطق، حراس، FSM، تحقق                                             ✅ كل الخدمات
```

القاعدة: **اختبر السلوك على أرخص مستوى يُثبته**. ما يعتمد على ذرّية Redis أو SQL حقيقي (ESCAPE، الفهارس، GETDEL)
لا تُثبته المحاكاة (mocks) — يُختبر في طبقة التكامل.

## 2. ما يُختبر في كل طبقة

### 2.1 وحدة (Jest / pytest / flutter test) — كل PR، < 2 دقيقة
- **الحراس والأمان:** `common/security.spec.ts` (رمز مزوّر، بلا توقيع، منتهٍ، دور غير مدير، سر داخلي قديم).
- **منطق الأعمال:** FSM المعاملات، حساب التقييم، ملكية الإعلان، حدود الترقيم، حالات الإعلان المسموحة.
- **سلوك سلبي إلزامي:** كل ثغرة تُغلق يرافقها اختبار يفشل على الكود القديم (مثال: `should not accept the old static code 123456`).
- **الأسرار في الاختبارات:** `jest.setup-env.js` لكل خدمة يضبط أسراراً وهمية؛ الكود نفسه لا يحوي أي قيمة افتراضية.

### 2.2 تكامل (`npm run test:int`) — كل PR، Postgres 16 + Redis 7 كخدمات في CI
| الملف | ماذا يُثبت |
|---|---|
| `auth-service/test/integration/redis-otp.int-spec.ts` | `SET NX`/`INCR+EXPIRE NX`/`GETDEL`/`SCAN` ذرية فعلاً؛ 30 تخميناً متوازياً لرمز OTP لا تتجاوز حد المحاولات |
| `listings-service/test/integration/listings.int-spec.ts` | المخطط من ملفات الترحيل الحقيقية؛ صفحات محدودة ومرتبة؛ المحذوف لا يظهر؛ `%` و`_` حرفيان؛ مزامنة المشاهدات لا تفقد زيادات |

كل ملف ينشئ مخططاً (schema) معزولاً ويحذفه، فيمكن تشغيله على قاعدة مشتركة.

**تشغيل محلي:**
```bash
docker run -d -p 5432:5432 -e POSTGRES_PASSWORD=pg postgres:16-alpine
docker run -d -p 6379:6379 redis:7-alpine
cd services/listings-service
DATABASE_URL=postgres://postgres:pg@localhost:5432/postgres REDIS_URL=redis://localhost:6379 npm run test:int
```

### 2.3 عقود ⏳ (المرحلة 1 — البنية)
اكتُشفت فروقات بين مسارات العملاء والخادم (القسم 2.6 في الخطة). الخطة:
1. سكربت يستخرج مسارات الخادم (`@Controller` + الدوال) ومسارات العملاء (`api.get('/..')`, `dio.get`) وخريطة البوابة، ويفشل عند أي مسار عميل بلا مقابل.
2. اختبار e2e للبوابة (`proxy.e2e.spec.ts`) موجود ويغطي التوجيه والحظر وتمرير multipart/webhook — يُوسَّع لكل بادئة.

### 2.4 حمل (k6) — يدوي عبر **Actions → Load tests**
- `listings-browse-load.js` معدل وصول ثابت حتى **500 RPS**، عتبات: `p95<300ms`، `p99<800ms`، أخطاء `<1%`.
- `auth-load.js`: محاولات الدخول الخاطئة تُرفض بـ 401/429 ولا 5xx.
- يُشغَّل على staging مع بيانات بحجم واقعي (≥ 100 ألف إعلان) — الأداء على جدول فارغ لا يعني شيئاً.

### 2.5 E2E ⏳ (المرحلة 3)
رحلات حرجة فقط: التسجيل بـ OTP → نشر إعلان بصورة → محادثة → معاملة → تقييم. Playwright للويب، `integration_test` لـ Flutter.

## 3. بوابات الجودة في CI (`.github/workflows/ci.yml`)

| الوظيفة | يفشل إذا |
|---|---|
| `secrets-guard` | عاد أي سر افتراضي مسرّب إلى الكود |
| `node-workspace` / `node-standalone` | خطأ أنواع (`tsc --noEmit`) أو اختبار وحدة فاشل — **9 خدمات** (كان 7، وكان `npm ci` يفشل فيها لعدم وجود ملف قفل) |
| `integration` | فشل اختبار على Postgres/Redis حقيقيين |
| `python` | فشل pytest (الاعتماديات مثبتة الإصدار الآن) |
| `web` | خطأ أنواع، اختبار، أو فشل `next build` |
| `flutter` | فشل `flutter test` (التحليل تحذيري مؤقتاً) |

لم يعد أي اختبار `continue-on-error`. ESLint للخدمات غير مُعدّ (ESLint 9 بلا ملف إعداد) — يُضاف كإعداد مشترك في المرحلة 1، ويحل `tsc` محله مؤقتاً.

## 4. أهداف التغطية
لا نطارد نسبة إجمالية. الإلزامي:
- **100%** من الحراس والتحقق من الرموز والأسرار وwebhooks (موجود).
- كل endpoint يغيّر بيانات: اختبار صلاحية سلبي واحد على الأقل (غير مالك / غير مشارك / غير مدير).
- كل استعلام قائمة: اختبار يثبت الحد الأقصى للصفحة.

## 6. الخطوات التالية
1. سكربت العقود + إصلاح الفروقات (مع خطوة البنية).
2. ترحيلات موحدة، ووظيفة CI تطبّقها كلها على قاعدة فارغة (تفشل الآن لغياب جدول `users` الأساسي).
3. اختبارات تكامل لـ transactions (قيد `UNIQUE` على التقييم، ذرية المعاملة) وmessaging (Postgres ✅ مضاف: الإرسال المتزامن، والصفحات، وخطط الاستعلام).
4. E2E للرحلات الحرجة، وتقرير k6 دوري على staging.
